# ADR 003 — One C ABI, cbindgen, XCFramework

- Status: accepted
- Date: 2026-09-13
- Amended: 2026-09-13. Named the UI snapshot mechanism. Stated the inward foreign-pointer rule: the shell owns a `CAMetalLayer` pointer, guarantees it outlives the borrow, and the core may not assume the address is stable. Phase 0 does not export a symbol for it.

## Context

AppKit, a future Win32 shell, and a future GTK shell must call the same engine. The boundary has to outlive Rust type layouts. Passing `String`, `Vec`, or a trait object into Swift ties every shell to the Rust compiler we happened to use that week.

The macOS shell wants a Swift-shaped API. That convenience must sit on our side of the boundary, not become the boundary.

## Decision

`llamp-ffi` exports a C ABI. Types on the wire travelling outward are handles (`void*` or an integer id), POD structs, explicit buffer pointer plus length, and integer error codes. Rust lifetimes do not cross the boundary. The caller owns buffers it passes in. The core owns buffers it returns, and the header documents the free function for each of them.

UI snapshots (position, VU, spectrum bins) are a seqlock or a triple buffer plus an atomic frame counter. The shell polls. It never waits on the audio callback, and the publisher of the snapshot takes no lock the audio callback would have to take.

A foreign platform pointer may travel inward. That is the exception to “Rust types do not cross,” and it is how phase 7 builds a wgpu surface from a shell-owned `CAMetalLayer`. It crosses only as an opaque `void*`. Phase 0 does not export a symbol for it.

The shell owns the pointer. It allocated the `NSView` and the layer embedded in that view. The core does not own it, does not free it, and does not `release` it.

The shell guarantees the object outlives every borrow the core holds. A borrow is the call that received the pointer and, once a surface exists, the interval until the shell tells the core that surface is done. The shell does not release or replace the layer while a borrow is outstanding. Ending the surface does not release the view.

The core may not assume the pointer is a Rust reference it can store, that the address is stable across resize or layer replacement, or that a pointer from an earlier call is still the layer the shell will pass next. It may not treat the layer and the view as the same object.

`cbindgen` generates the header from that crate. The header is checked in so a Swift or C reviewer can see a diff when the ABI moves. A CI job fails if the checked-in header does not match cbindgen output.

On macOS the static library is wrapped in an XCFramework built in CI, then a hand-written Swift package maps handles to Swift types. The Swift package is not the ABI. Windows and Linux link the same C symbols. They do not consume the Swift package.

Phase 0 freezes a version function returning a C string, and two probes: a 64 KB buffer plus its free function, and a counter the shell polls at 60 Hz. The inward layer pointer is not one of them. Further symbols are added in the phase that needs them and named in that phase’s notes. This ADR does not list a fake header.

## Consequences

- Three shells share one contract.
- ABI changes are visible in a header diff.
- The Swift wrapper can be idiomatic without leaking that idiomatic shape into Rust.
- We write more glue than `uniffi` would generate for Swift alone. That glue is the product.
- A wrong free function leaks or double-frees in every shell. Phase 0’s buffer probe is the test that retires that before a skin atlas exists.
- A foreign pointer the core treats as its own, or uses after the shell ends the borrow, is a use-after-free. The shell owns the layer for the view’s life. Dropping the surface does not drop the view. Resize and layer replacement are a phase 7 investigation, not a phase 0 symbol.

## Alternatives

- **uniffi.** Rejected as the stable boundary. It generates comfortable Swift and it owns the type model. A Windows shell should not depend on a Rust binding generator’s object runtime. uniffi is a reasonable Swift shortcut and a bad three-shell ABI.
- **Hand-written headers.** Rejected as the source of truth. They drift from the Rust structs. cbindgen is the source of truth; the checked-in header is the review artifact.
- **cxx.** Rejected: C++ types help neither Swift nor a C plugin ABI.
- **A Swift package that hides Rust without a C header.** Rejected: Linux and Windows would have nothing stable to call.
